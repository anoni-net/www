社区运作到一定规模之后，需要把决策的方式写下来，才不必每次重新争论基本原则。本章程规范 anoni.net 社区的成员角色、决策方式、争议处理与行为准则，属于持续修订的活文件，重大调整都先在 Matrix 公开讨论，再提交修订。

第一次参与的成员可以先略读「成员角色」、「行为准则」两节，了解社区对成员的基本期待。资深成员、提案者与需要处理争议的核心成员，建议完整读过一遍。

## 适用范围

本章程适用于以下范畴的协作与互动：

- anoni.net 文档站（zh-TW、zh-CN、en）
- 自架的 Matrix 家服务器 `im.anoni.net`、CryptPad、Etherpad、Send、SearXNG、Formbricks
- 以 anoni.net 名义举办的工作坊、小聚与研讨会场次
- 与 EFF、Tor Project、OONI 等国际组织合作时的对外代表
- 社区相关 GitHub repo 的 PR、Issue 与 Discussion

成员以个人身份在外部平台的言行不在本章程的范围内，在 anoni.net 场域内的言行则需符合本章程。

## 成员角色

社区的角色制度维持低度形式化，以免层级让新人感到疏离。各角色实际的权限差别主要在账号层面（谁能合并 PR、谁能审核 Matrix 账号申请），发言的权重没有差别。

### 核心成员

核心成员长期投入运维，累积了足够的技术能力与社区信任，负责以下事项：

- 自架服务的运维与账号审核
- GitHub repo 的合并权限
- 对外代表 anoni.net 与国际组织交涉
- 章程修订提案的最终把关
- 处理违反行为准则的争议

新的核心成员需经现有核心成员以共识决同意才能加入，目前没有公开的申请流程。

### 贡献者

贡献者是有具体产出的成员，产出包括文章、翻译、程序、活动筹备、设计与研究等，并在 Matrix Public Space 的相关 room 积极参与。

加入方式：在[参与](/join/)页认领主题、提交 PR，或参与活动筹备，没有正式门槛。

### 观察员

观察员订阅了电子报、加入了 Public Space，但暂时没有具体产出。社区以异步的方式运作，不要求每个人都保持活跃，观察员同样受到欢迎。

### 访客

访客没有加入 Matrix，通过阅读文档与博客、来信讨论接触社区。寄到 <whisper@anoni.net> 的邮件由核心成员轮值处理。

## 决策方式

### 共识决

社区以共识决为基本的决策方式。共识指相关成员都没有提出反对，不要求全员同意。流程如下：

1. 提案者在 Matrix 对应的 room 提出提案，附上脉络与选项
2. 至少保留 3 天，让有意见的成员回应
3. 没有反对意见即视为通过
4. 有反对意见时进入讨论，直到讨论出双方都能接受的版本

大多数的内容、流程与设计决策都适用共识决。

### 投票（例外状况）

只有在共识决明显受阻，或时间紧迫需要尽快得出结论时，才改用投票。投票的条件如下：

- 由至少两位核心成员发起
- 投票资格：所有贡献者（最近 6 个月内有具体产出的成员）
- 投票方式：Matrix Poll 公开投票，或 CryptPad 表单半匿名投票
- 通过门槛：简单多数（过半）
- 重大议题（章程修订、核心成员加入或退出）需 2/3 多数

社区目前几乎没有进行过投票，多数情况以共识决就能解决。

### 提案流程

| 影响范围 | 提案渠道 | 决策方式 |
|---|---|---|
| 单篇文章内容、翻译选词 | GitHub PR 或 Matrix room | review 时取得共识 |
| 结构性变动（调整导航、搬移文件、更改命名） | 先在 Matrix room 讨论，再提交 PR | 共识决，3 天缓冲 |
| 自架服务的新增、移除与政策变更 | Matrix 核心 room 与公开 room 同时进行 | 核心成员共识决 |
| 章程、行为准则修订 | GitHub Issue 与 Matrix 同时进行 | 共识决，至少 7 天缓冲 |
| 对外公开立场（声明、抗议、支持书） | Matrix 公开 room | 核心成员与多数贡献者同意 |

## 争议处理

争议分成对事与对人两类。对事的争议关于如何做某件事，对人的争议涉及互动冲突或违反行为准则。

### 对事的争议

对事的争议依一般的提案流程处理，在 Matrix 提出歧见、列出双方论点并寻求共识，无法取得共识时进行投票。技术性的争议可以保留分歧、各自实验，一段时间后再依结果评估。

### 对人的争议

成员之间的互动冲突依严重程度分流处理：

1. **轻微误解**：相关成员私下沟通即可
2. **明确违反行为准则**：受影响者可向核心成员回报，由核心成员协助处理（私下对话、公开警告、暂时隔离）
3. **严重事件**（骚扰、跟踪、人身威胁）：核心成员立即移除违规成员的访问权限，事后在公开 room 简述处置（不揭露受害者身份），并视需要协助受害者报警或联系援助资源

涉及核心成员自身的争议，由其他核心成员处理，必要时邀请外部仲裁。

## 行为准则

### 互动原则

- **互相尊重**：不同背景、技术熟悉度与政治立场的成员一视同仁
- **对事不对人**：批评想法，不批评身份
- **默认善意**：先假设对方的提议出自善意，再讨论细节
- **信息透明**：相关决策尽量在公开 room 进行，私下协调的结果事后同步到公开 room
- **新人友善**：对基本问题保持耐心，把复杂的脉络拆解清楚

### 合法前提

所有协作与讨论以合法用途为前提，社区不协助也不指导以下行为：

- 洗钱、规避税务、规避经济制裁
- 骚扰、跟踪、人身威胁、未授权入侵
- 散布儿少性剥削内容、人口贩运、毒品交易
- 在他国对该国公民进行情报搜集或干预内政

各种人都可能使用匿名与隐私保护工具，社区推广时以新闻媒体、公民团体、研究者与需要保护自己的个人为对象。发现协作对象有上述违法意图时，社区会立即终止协作。

### 机敏信息处理

- 涉及个人数据、未公开研究、敏感受害者身份的内容，依[上传机敏信息流程](/join/upload-sensitive/)处理
- 不在公开 room 直接张贴受害者个人数据或未公开的爆料原文
- 引用敏感报道时保留原作者与来源，不擅自摘要敏感细节

### 对外言行

代表 anoni.net 对外发言（媒体访问、活动致词、社交账号）时，需遵守以下原则：

- 避免发表未经社区讨论的政治立场
- 引述社区成员的私下意见前，需取得当事人同意
- 与国际组织（EFF、Tor Project、OONI）交涉前，先在 Matrix 同步

成员以个人身份对外发言时，注明「个人立场，不代表社区」。

## 违反处置

违反行为准则的处置由核心成员依个案决定，可能的处置由轻至重如下：

1. **私下提醒**：核心成员私信提醒，不留公开记录
2. **公开警告**：在相关的 Matrix room 公开记录违规行为
3. **暂时隔离**：暂停 Matrix 账号、CryptPad 访问与 GitHub 权限，期间数天到数周
4. **永久移除**：撤销所有自架服务的账号、合作关系，以及参与社区相关活动的资格

核心成员决定处置时，会考量违规的严重程度、是否累犯与当事人的态度。重大事件的处置决定会在公开 room 简述，不揭露受害者身份。

## 章程修订

本章程是活文件，任何人都可以提案修订，流程如下：

1. 在 GitHub 开 Issue，说明要修改的内容与理由
2. 同时在 Matrix 公开 room 通知
3. 保留至少 7 天的讨论期
4. 取得共识后，由核心成员合并进 `main`，并在博客简短说明异动

遇到紧急状况（例如出现新型骚扰手法，需要立即更新处置原则），核心成员可以先行临时更新，并在 7 天内回到正规程序检讨。
