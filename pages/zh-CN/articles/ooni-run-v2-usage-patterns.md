全世界的 OONI Run v2 累积产出 1,417 万笔检测，其中 72% 来自 3 条清单。占比最高的几条清单做法相同，每条只针对一个特定的审查或封锁现象，由持续运行的测量后端定期执行、长期累积数据。我们普查了全部的 Run v2 检测链接，量出集中的程度，也整理出这套做法对想做本地连接观测的社区有哪些参考价值。

OONI Run v2 让任何人自行编一份网站清单、生成一条链接，其他人用 OONI Probe 打开链接就会照清单测一轮，结果一律进入 OONI 的公开数据集（操作方式见文档站的 [OONI Run v2 操作说明](docs:tools/ooni-run-v2/)）。不必写程序就能定义自己的观测目标，但知道、用过的人不多，我们因此想盘点它实际的使用方式。

## 普查方法

我们以 2026-06-01 为快照，盘点 OONI Run v2 上全部存活的 336 条检测链接，逐条用 OONI 的 aggregation API[^1] 取得生涯检测量，再依清单主题分群。下文的数字都以这个快照为准，数据来源与前提整理在文末。

## 母体规模

OONI Run v2 从 2024-04-24 第一条检测链接上线到快照日约 26 个月，全世界总共只创建过 337 条检测链接（其中 1 条已删除，现存 336 条）。创建数在 2024 年 10 到 12 月冲高，之后稳定在每月 10 到 19 条。共有 157 个不重复的作者，332 条使用网络连接测试（Web Connectivity），几乎都在测网站可达性。

![每月新建的 Run v2 检测链接数量](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-1.zh-CN-72eb4058.png)

对全球性的审查观测工具来说，两年 337 条并不多，只看创建数很容易得到「Run v2 没什么人用」的结论，下一节的使用量数据会推翻它。

## 使用量的集中程度

336 条检测链接的生涯检测量合计 14,171,627 笔，总量不算少，但分布极不平均。以检测量计算的基尼系数（Gini coefficient）是 0.981，逼近完全不均的 1.0。

!!! note "选用基尼系数的理由"

    基尼系数原本用来衡量收入分配的不平均，数值介于 0 到 1，把整个分布的集中程度浓缩成一个数字。0 代表完全平均，每条检测链接的检测量相同。1 代表完全集中，所有检测都来自同一条检测链接。

    每条检测链接的检测量都是非负的数量，要回答的问题又刚好是全网检测量有多集中在少数检测链接上，适合用基尼系数衡量。基尼系数在数学上等于洛伦兹曲线（Lorenz curve）与对角线之间的面积（再除以对角线下方的总面积），所以下方的洛伦兹曲线越贴着底边，基尼系数就越接近 1。0.981 代表分布已经很接近少数检测链接占掉几乎全部检测的极端。

    单一数字看不出集中在哪几条检测链接，也看不出长尾的形状，因此另附洛伦兹曲线与分级分布两张图。

检测量的洛伦兹曲线（虚线为完全平均的对角线）

![检测量的洛伦兹曲线（虚线为完全平均的对角线）](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-2.zh-CN-315a4d3f.png)

洛伦兹曲线几乎贴着底边走，到最后一段才垂直拉起。检测量最少的 90% 检测链接加起来只占全网的 0.93%，最少的 99% 也只占 20.45%。排在最前面的 4 条检测链接就占约 79.5%，单是第一名（DW 的 Global media，编号 `10006`）就占 46.5%。

分布的另一端，336 条检测链接里有 112 条（33%）生涯检测量是 0，创建后几乎没被执行过。有 193 条（57%）不到 100 笔，整体中位数只有 27 笔，多数检测链接创建后只执行过几次。

## 清单大小与生涯检测量

直觉上，清单收录的网站越多，产出的数据应该越多。把每条检测链接的清单大小（input 数）对生涯检测量画成散点图，两者却几乎没有关系。

清单大小与生涯检测量（橘色为 anoni.net 的两条检测链接，2 条 input 为 0 的检测链接因 log 轴略去）

![清单大小与生涯检测量（橘色为 anoni.net 的两条检测链接，2 条 input 为 0 的检测链接因 log 轴略去）](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-5.zh-CN-e5ae51a8.png)

UCU 的 `10158` 收录 4,635 个 input（全网最大），生涯检测量 734,627 笔。DW 的 `10004` 只有 15 个 input，却有 582,480 笔。清单再大，没有持续运行的后端去执行，检测量一样趋近 0，等于没有在观测。让观测累积下来的是每天执行清单的测量基础设施，收录多少网站是其次。

## anoni.net 社区的两条检测链接

anoni.net 社区先后创建两条 Run v2 检测链接，刚好对应前面的两种样态，两条都列出来，不只挑表现好的那条。

第一条是 2025-09-15 创建的 `10238`，收录 7 个 input（anoni.net 与 im、matrix、form、pad、search、cinny 等自家服务），生涯只累积 14 笔，属于创建后没有持续执行的多数。

第二条是 2026-05-15 创建的 `10328`，清单扩充到 10 个 input，并由自营节点持续执行。半个月累积 4,659 笔，在 336 条检测链接里排第 39 名，落在前 12%。

同一个社区、同一份自家服务清单的雏形，两条检测链接的差别只在有没有持续运行的后端。`10328` 占全网的比重仍然趋近 0%，但在长尾如此明显的分布里，持续执行半个月就超过 297 条检测链接，多数检测链接都没有跨过持续运行的门槛。

## 对社区与 OONI 的意义

对想做本地连接观测的社区，Run v2 的价值来自针对特定现象的策展清单加上持续运行的测量后端，两者缺一就会落入长尾，多开几条检测链接本身不会带来数据。

前面提到的 DW、conexionsegura、vesinfiltro 分别在观测国际媒体可达性、体育盗版封锁与本地封锁，同一套模式也能套用在其他题目上，例如下列几个方向。

- **选举观察**：从选前到选后持续追踪新闻媒体、候选人与选举机构网站在特定地区的可达性，记录投票期间的封锁或干扰，为选举观察员与研究者提供可佐证的时间序列。
- **重大事件实时观测**：抗议、罢工、灾害或断网期间持续检测独立媒体、即时通信服务（Signal、Telegram）与求助信息网站，实时掌握哪些网站遭到封锁、何时开始。
- **特定群体与议题**：对 LGBTQ+、宗教少数、女性权益与人权组织等在部分地区容易遭到封锁的网站做长期纵贯观测，累积可供研究引用的证据。
- **规避工具可用性**：追踪 VPN、Tor、桥接与其他规避工具（circumvention tools）的官网与下载地址在某地是否仍可连接、何时开始遭到封锁，对协助当地人维持连接的团体特别有用。
- **跨境媒体与离散社区**：观测离散社区依赖的境外媒体（中文读者熟悉的例如 RFA、端传媒）在不同 ASN 的可达性差异与长期变化。
- **平台级封锁事件**：某个 app 或服务在某国突然遭到封锁时，迅速创建一条清单跨 ASN 观测，量出封锁的范围与起止时间，留下可分析的数据。

挑一个最关心的题目，列出十来个相关网站，再让一个节点每天执行，几周后就有自己的可达性时间序列可以分析。

OONI 团队与做数据分析的伙伴可以利用 aggregation API 的 `ooni_run_link_id` 筛选条件，针对 Run v2 的整体使用情况做 meta 分析，本篇报告即以此方式产出。

## 数据与前提

本篇数据以 2026-06-01 为快照，逐条取自 OONI 公开的 aggregation API[^1]（以 `ooni_run_link_id` 筛选）。检测量会随时间继续累积，之后重查会得到略高的数字，集中的形状则维持稳定。解读时的几个前提：

- 检测量来自 aggregation API 的 `measurement_count`，是 2026-06-01 当下的查询结果，之后仍会增加。
- 生涯查询涵盖 `2024-01-01` 到 `2026-06-30`，包含 Run v2 的完整历史。
- 检测量为 0 的检测链接可能是测试或草稿用途，不一定代表失败。
- 任何国家的 probe 都能执行同一条检测链接，使用情境的分群依清单主题推断，并非 OONI 的官方标注。
- 完整揭露：社区自己的两条检测链接（`10238`、`10328`）都列进分析与讨论，没有只挑表现好的 `10328`。
