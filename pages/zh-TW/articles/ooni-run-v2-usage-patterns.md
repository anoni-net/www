全世界的 OONI Run v2 累積產出 1,417 萬筆檢測，其中 72% 來自 3 條清單。佔比最高的幾條清單做法相同，每條只針對一個特定的審查或封鎖現象，由持續運行的測量後端定期執行、長期累積資料。我們普查了全部的 Run v2 檢測連結，量出集中的程度，也整理出這套做法對想做在地連線觀測的社群有哪些參考價值。

OONI Run v2 讓任何人自行編一份網站清單、產生一條連結，其他人用 OONI Probe 開啟連結就會照清單測一輪，結果一律進入 OONI 的公開資料集（操作方式見文件站的 [OONI Run v2 操作說明](docs:tools/ooni-run-v2/)）。不必寫程式就能定義自己的觀測目標，但知道、用過的人不多，我們因此想盤點它實際的使用方式。

## 普查方法

我們以 2026-06-01 為快照，盤點 OONI Run v2 上全部存活的 336 條檢測連結，逐條用 OONI 的 aggregation API[^1] 取得生涯檢測量，再依清單主題分群。下文的數字都以這個快照為準，資料來源與前提整理在文末。

## 母體規模

OONI Run v2 從 2024-04-24 第一條檢測連結上線到快照日約 26 個月，全世界總共只建立過 337 條檢測連結（其中 1 條已刪除，現存 336 條）。建立數在 2024 年 10 到 12 月衝高，之後穩定在每月 10 到 19 條。共有 157 個不重複的作者，332 條使用網路連線測試（Web Connectivity），幾乎都在測網站可達性。

每月新建的 Run v2 檢測連結數量

![每月新建的 Run v2 檢測連結數量](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-1.zh-TW-30a1170f.png)

對全球性的審查觀測工具來說，兩年 337 條並不多，只看建立數很容易得到「Run v2 沒什麼人用」的結論，下一節的使用量資料會推翻它。

## 使用量的集中程度

336 條檢測連結的生涯檢測量合計 14,171,627 筆，總量不算少，但分佈極不平均。以檢測量計算的吉尼係數（Gini coefficient）是 0.981，逼近完全不均的 1.0。

!!! note "選用吉尼係數的理由"

    吉尼係數原本用來衡量所得分配的不平均，數值介於 0 到 1，把整個分佈的集中程度濃縮成一個數字。0 代表完全平均，每條檢測連結的檢測量相同。1 代表完全集中，所有檢測都來自同一條檢測連結。

    每條檢測連結的檢測量都是非負的數量，要回答的問題又剛好是全網檢測量有多集中在少數檢測連結上，適合用吉尼係數衡量。吉尼係數在數學上等於羅倫茲曲線（Lorenz curve）與對角線之間的面積（再除以對角線下方的總面積），所以下方的羅倫茲曲線越貼著底邊，吉尼係數就越接近 1。0.981 代表分佈已經很接近少數檢測連結佔掉幾乎全部檢測的極端。

    單一數字看不出集中在哪幾條檢測連結，也看不出長尾的形狀，因此另附羅倫茲曲線與分級分佈兩張圖。

檢測量的羅倫茲曲線（虛線為完全平均的對角線）

![檢測量的羅倫茲曲線（虛線為完全平均的對角線）](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-2.zh-TW-290a0f49.png)

羅倫茲曲線幾乎貼著底邊走，到最後一段才垂直拉起。檢測量最少的 90% 檢測連結加起來只佔全網的 0.93%，最少的 99% 也只佔 20.45%。排在最前面的 4 條檢測連結就佔約 79.5%，單是第一名（DW 的 Global media，編號 `10006`）就佔 46.5%。

每條檢測連結的生涯檢測量落在哪個級距

![每條檢測連結的生涯檢測量落在哪個級距](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-3.zh-TW-abfaf459.png)

分佈的另一端，336 條檢測連結裡有 112 條（33%）生涯檢測量是 0，建立後幾乎沒被執行過。有 193 條（57%）不到 100 筆，整體中位數只有 27 筆，多數檢測連結建立後只執行過幾次。

## 清單大小與生涯檢測量

直覺上，清單收錄的網站越多，產出的資料應該越多。把每條檢測連結的清單大小（input 數）對生涯檢測量畫成散點圖，兩者卻幾乎沒有關係。

清單大小與生涯檢測量（橘色為 anoni.net 的兩條檢測連結，2 條 input 為 0 的檢測連結因 log 軸略去）

![清單大小與生涯檢測量（橘色為 anoni.net 的兩條檢測連結，2 條 input 為 0 的檢測連結因 log 軸略去）](https://assets.anoni.net/www/articles/ooni-run-v2-usage-patterns-5.zh-TW-89c40f72.png)

UCU 的 `10158` 收錄 4,635 個 input（全網最大），生涯檢測量 734,627 筆。DW 的 `10004` 只有 15 個 input，卻有 582,480 筆。清單再大，沒有持續運行的後端去執行，檢測量一樣趨近 0，等於沒有在觀測。讓觀測累積下來的是每天執行清單的測量基礎設施，收錄多少網站是其次。

## anoni.net 社群的兩條檢測連結

anoni.net 社群先後建立兩條 Run v2 檢測連結，剛好對應前面的兩種樣態，兩條都列出來，不只挑表現好的那條。

第一條是 2025-09-15 建立的 `10238`，收錄 7 個 input（anoni.net 與 im、matrix、form、pad、search、cinny 等自家服務），生涯只累積 14 筆，屬於建立後沒有持續執行的多數。

第二條是 2026-05-15 建立的 `10328`，清單擴充到 10 個 input，並由自營節點持續執行。半個月累積 4,659 筆，在 336 條檢測連結裡排第 39 名，落在前 12%。

同一個社群、同一份自家服務清單的雛形，兩條檢測連結的差別只在有沒有持續運行的後端。`10328` 佔全網的比重仍然趨近 0%，但在長尾如此明顯的分佈裡，持續執行半個月就超過 297 條檢測連結，多數檢測連結都沒有跨過持續運行的門檻。

## 對社群與 OONI 的意義

對想做在地連線觀測的社群，Run v2 的價值來自針對特定現象的策展清單加上持續運行的測量後端，兩者缺一就會落入長尾，多開幾條檢測連結本身不會帶來資料。

前面提到的 DW、conexionsegura、vesinfiltro 分別在觀測國際媒體可達性、體育盜版封鎖與在地封鎖，同一套模式也能套用在其他題目上，例如下列幾個方向。

- **選舉觀察**：從選前到選後持續追蹤新聞媒體、候選人與選務機關網站在特定地區的可達性，記錄投票期間的封鎖或干擾，提供選舉觀察員與研究者可佐證的時間序列。
- **重大事件即時觀測**：抗議、罷工、災害或斷網期間持續檢測獨立媒體、即時通訊服務（Signal、Telegram）與求助資訊網站，即時掌握哪些網站遭到封鎖、何時開始。
- **特定族群與議題**：對 LGBTQ+、宗教少數、女性權益與人權組織等在部分地區容易遭到封鎖的網站做長期縱貫觀測，累積可供研究引用的證據。
- **規避工具可用性**：追蹤 VPN、Tor、橋接與其他規避工具（circumvention tools）的官網與下載點在某地是否仍可連線、何時開始遭到封鎖，對協助當地人維持連線的團體特別有用。
- **跨境媒體與離散社群**：觀測離散社群依賴的境外媒體（正體中文使用者熟悉的例如 RFA、端傳媒）在不同 ASN 的可達性差異與長期變化。
- **平台級封鎖事件**：某個 app 或服務在某國突然遭到封鎖時，迅速建立一條清單跨 ASN 觀測，量出封鎖的範圍與起訖時間，留下可分析的資料。

挑一個最關心的題目，列出十來個相關網站，再讓一個節點每天執行，幾週後就有自己的可達性時間序列可以分析。

OONI 團隊與做資料分析的夥伴可以利用 aggregation API 的 `ooni_run_link_id` 篩選條件，針對 Run v2 的整體使用情形做 meta 分析，本篇報告即以此方式產出。

## 資料與前提

本篇資料以 2026-06-01 為快照，逐條取自 OONI 公開的 aggregation API[^1]（以 `ooni_run_link_id` 篩選）。檢測量會隨時間繼續累積，之後重查會得到略高的數字，集中的形狀則維持穩定。解讀時的幾個前提：

- 檢測量來自 aggregation API 的 `measurement_count`，是 2026-06-01 當下的查詢結果，之後仍會增加。
- 生涯查詢涵蓋 `2024-01-01` 到 `2026-06-30`，包含 Run v2 的完整歷史。
- 檢測量為 0 的檢測連結可能是測試或草稿用途，不一定代表失敗。
- 任何國家的 probe 都能執行同一條檢測連結，使用情境的分群依清單主題推斷，並非 OONI 的官方標註。
- 完整揭露：社群自己的兩條檢測連結（`10238`、`10328`）都列進分析與討論，沒有只挑表現好的 `10328`。
